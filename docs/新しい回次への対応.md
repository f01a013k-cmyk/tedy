# 新しい公募回次に対応する手順

公募要領は回次ごとに金額・様式・審査観点が変わります。
コードを触る必要はなく、ナレッジファイルの追加だけで対応できます。

## 手順

### 1. ナレッジファイルを複製する

```bash
cp src/jizokuka/knowledge/koubo_r17.yaml src/jizokuka/knowledge/koubo_r18.yaml
```

`meta` を更新します。

```yaml
meta:
  koubo_id: r18
  display_name: 第18回 小規模事業者持続化補助金〈一般型〉
  source_url: https://...
  verified: false
```

### 2. 突合チェックリストを出す

```bash
jizokuka koubo --koubo r18 --verify
```

出力されたチェックリストを、公募要領PDFと1項目ずつ照合します。
特に変わりやすいのは次の箇所です。

- 申請枠の種類と補助上限額・補助率
- 上乗せ特例（インボイス特例など）の有無と金額
- 補助対象経費の区分（区分の追加・統合が起きる）
- ウェブサイト関連費の上限割合、設備処分費の上限割合
- 相見積が必要になる金額の閾値
- 様式2の項目構成と記入欄の分量
- 審査の観点と配点

### 3. 検証済みにする

全て照合できたら `meta.verified: true` と `verified_by` / `verified_at` を記入します。
これをしないと、生成物すべてに未検証警告が付きます。

### 4. 動作確認

```bash
python -c "from jizokuka.knowledge import load_koubo; print(load_koubo('r18').display_name)"
pytest tests/test_knowledge.py
```

`load_koubo` は読み込み時に静的検証を行い、以下を検出します。

- 必須キーの欠落
- **YAML 1.1 の真偽値キー事故**（`no:` が `False` になる。必ずクォートする）
- セクションキーの重複
- 未定義の審査観点への参照
- 解釈できない補助率

### 5. 案件で使う

```bash
jizokuka new tanaka --from hearing.yaml --koubo r18
```

既存案件は `projects/<案件ID>/hearing.yaml` の `koubo_id` を書き換えてから
`jizokuka build` し直してください。

## 注意

`max_chars` は公募要領上の明示的な文字数制限ではなく、
様式の記入欄に収まる**実務上の目安**です（`project_name` の30字のみ様式上の絶対上限で、
`hard_limit: true` を付けています）。
実際の様式ファイルの記入欄サイズに合わせて調整してください。
